# ReelBot: спецификация проекта

Телеграм-бот для автоматического монтажа вертикальных роликов (Reels / TikTok / Shorts):
анимированные пословные субтитры, вырезание пауз, автокроп 9:16, вставка картинок по смыслу.

Документ предназначен для пошаговой реализации. Работаем строго по вехам M0..M8.
**Одна сессия = одна веха.** Не начинай следующую, пока текущая не прошла свой Definition of Done.

---

## 0. Архитектурный принцип

Единственная идея, из которой следует всё остальное:

```
Восприятие (детерминированное)  →  LLM-режиссёр (JSON)  →  Рендерер (тупой)
```

**EDL (Edit Decision List)** это контракт системы. LLM никогда не рендерит и никогда
не считает арифметику. Она только возвращает JSON со ссылками на индексы слов.
Рендерер никогда не принимает решений, он исполняет EDL буквально.

Следствия, которые нельзя нарушать:

1. LLM **не возвращает таймкоды**. Только `word_idx`. Таймкоды подставляет Python
   из вывода ASR. Модели ошибаются в арифметике с float, это источник съехавших
   субтитров.
2. Анимация это **код, а не модель**. Плавное появление, glass-панель, ghost-слова,
   рост контейнера, затухание блока, всё детерминированно.
3. Пресет стиля это **данные (JSON), а не код**. Добавление нового стиля не должно
   требовать правки компонентов.
4. Любой EDL должен переживать перерендер. Сохранённый EDL + другой пресет = новое
   видео без повторного ASR и LLM.

## 1. Стек

| Слой | Технология | Почему |
|---|---|---|
| Бот | Python 3.12, aiogram 3 | async, зрелый |
| Bot API | локальный `telegram-bot-api` в docker | лимит файла 2 ГБ вместо 20 МБ |
| Очередь | arq + Redis | нативно async, легче Celery |
| БД | PostgreSQL + SQLAlchemy 2 (async) | задачи, EDL, юзеры |
| Хранилище | MinIO (S3-совместимое) | исходники, результаты, кеш картинок |
| ASR | WhisperX (large-v3) | пословное выравнивание |
| LLM | Anthropic API через один абстрактный клиент | см. §4 |
| Видео-препроцесс | ffmpeg 6+ | нарезка, кроп, звук |
| Рендер | Remotion (Node 20) | React-анимации, spring |
| Картинки | Pexels API → fallback на диффузию | сток дешевле генерации |

**Границы языков.** Python владеет пайплайном и состоянием. Node только рендерит.
Взаимодействие через `subprocess` с JSON на stdin и путём к файлу на stdout.
Никакого HTTP-сервиса между ними, это лишняя точка отказа.

## 3. Схема EDL

Определить в `src/core/edl.py` на pydantic v2. Это делается **первым делом** в M2,
до любой логики. Все enum строго закрытые, никаких свободных строк, иначе LLM начнёт
изобретать эффекты, которых нет в рендерере.

```python
class Word(BaseModel):
    idx: int          # позиция в исходном транскрипте
    text: str
    start: float      # сек, из ASR
    end: float

class Cut(BaseModel):
    src_in: float
    src_out: float
    reason: Literal["hook", "keep", "drop_silence", "drop_filler"]

class Emphasis(str, Enum):
    NONE = "none"
    ACCENT = "accent"      # крупно + акцентный цвет
    SHOUT = "shout"        # ещё крупнее + лёгкий поворот

class CaptionWord(BaseModel):
    word_idx: int
    emphasis: Emphasis = Emphasis.NONE
    emoji: str | None = None

class CaptionBlock(BaseModel):
    words: list[CaptionWord]           # 3-5 слов
    position: Literal["top", "center", "bottom", "auto"] = "auto"
    layout: Literal["stack", "ragged", "single_line"] = "stack"

class BrollAnim(str, Enum):
    POP_IN = "pop_in"
    SLIDE_UP = "slide_up"
    FULLSCREEN_TO_INSET = "fullscreen_to_inset"

class Broll(BaseModel):
    word_idx: int                      # к какому слову привязана
    duration: float = Field(ge=0.8, le=3.0)
    query: str                         # англ. поисковый запрос
    prompt: str | None = None          # для генерации, если стока нет
    anim: BrollAnim
    anchor: Literal["top_left", "top_right", "bottom_left",
                    "bottom_right", "center", "fullscreen"]

class CameraMove(BaseModel):
    word_idx: int
    type: Literal["zoom_punch", "shake"]
    scale: float = Field(ge=1.0, le=1.25)

class EDL(BaseModel):
    version: Literal[1] = 1
    source_duration: float
    words: list[Word]                  # заполняет Python, не LLM
    cuts: list[Cut]
    captions: list[CaptionBlock]
    broll: list[Broll] = []
    camera: list[CameraMove] = []
    preset: str = "glass"
```

**Валидатор семантики** (отдельно от pydantic, в `edl.py`):

- каждый `word_idx` существует в `words`
- каждое слово попадает ровно в один `CaptionBlock`, порядок сохранён
- `cuts` не пересекаются и отсортированы
- `len(broll) <= ceil(duration_sec / 8)` — жёсткий потолок, иначе LLM закидает
  картинками каждое второе слово
- в блоке не больше одного слова с `emphasis != NONE`

Провал валидации → один ретрай в LLM с текстом ошибки в промпте → фолбэк на
EDL без акцентов и b-roll (ролик всё равно соберётся).

## 4. LLM: где, какая, как

Один абстрактный клиент в `src/llm/client.py` с методом
`complete(prompt_name, vars, schema, model_tier)`. Тир, а не имя модели, в вызывающем коде.
Маппинг тиров на модели в конфиге, чтобы менять без правки логики.

| Вызов | Тир | Модель по умолчанию | Задача |
|---|---|---|---|
| `clean_transcript` | `cheap` | Haiku 4.5 | правки индексами: `{"i": 42, "fix": "..."}`. НЕ переписывание текста. |
| `direct` | `smart` | Opus 5 | cuts + разбивка на блоки + акценты. Главный вызов, качество продукта. |
| `plan_broll` | `vision` | Sonnet 5 | 3-4 кадра на вход, куда и какую картинку. |
| `metadata` | `cheap` | Haiku 4.5 | заголовок, описание, хештеги. |

Правила:

- Промпты живут в `src/llm/prompts/*.md`, не в питоновских строках.
- Системный промпт (стили + few-shot примеры EDL) идентичен между роликами →
  включить **prompt caching**, иначе переплата вдвое.
- Логировать `input_tokens`, `output_tokens`, `cache_read_tokens` в БД на каждый вызов.
  Себестоимость ролика надо видеть с первого дня.
- Ретрай ровно один. Второй провал → фолбэк, не третья попытка.

## 5. Вехи

### M0. Скелет и инфраструктура

- `docker-compose.yml`: postgres, redis, minio, `telegram-bot-api` (флаг `--local`)
- aiogram-бот подключён к локальному Bot API server
- alembic-миграции, таблицы `users`, `jobs`
- `.env.example` со всеми переменными

**DoD:** `docker compose up` поднимает всё; бот отвечает на `/start`; загрузка
видео на 60 МБ проходит и файл лежит в MinIO.

**Не делать:** обработку видео, LLM, очередь.

⚠ Локальный Bot API server отдаёт **локальные пути к файлам**, а не URL. Скачивание
через `bot.download_file()` работать не будет, читать напрямую с примонтированного тома.

---

### M1. ASR

- `probe.py`: ffprobe → длительность, fps, разрешение, наличие звука
- `audio.py`: извлечение моно 16 кГц wav
- `asr.py`: WhisperX large-v3 с форсированным выравниванием → `list[Word]`
- CLI: `python -m src.pipeline.asr <file> > words.json`

**DoD:** на тестовом видео из `tests/fixtures/` получаем JSON с пословными таймингами;
визуальная проверка: тайминги совпадают с речью в пределах 100 мс.

**Не делать:** LLM, рендер, бот.

⚠ Пины версий torch/CUDA. WhisperX ломается на мажорных апдейтах. Зафиксировать
в `pyproject.toml` точные версии.

---

### M2. EDL и режиссёр

- `core/edl.py`: модели + семантический валидатор (§3)
- `llm/client.py`: абстракция, structured output, retry, учёт токенов
- `llm/prompts/direct.md`
- `pipeline/director.py`: `words.json` → `edl.json`
- Тест на golden-файлах: 3 размеченных вручную примера

**DoD:** `words.json → edl.json`, валидатор зелёный на 10 прогонах подряд
(проверка стабильности, а не единичного успеха).

**Не делать:** b-roll, рендер.

---

### M3. Первый рендер через ASS  ← первый продаваемый результат

Быстрый путь, чтобы увидеть картинку на экране до Remotion.

- Генератор `.ass` из EDL: karaoke-теги `\k` для пословной подсветки,
  `\t` для масштаба, `\an` для позиции
- Вшивание: `ffmpeg -vf "subtitles=out.ass"`

**DoD:** на вход mp4 → на выход mp4 с работающими пословными субтитрами и
одним акцентным словом на блок.

**Не делать:** glass-панель, ghost-слова, b-roll. В ASS это делается плохо,
это работа для M5.

---

### M4. Очередь и бот

- arq-воркеры: три пула (`gpu`, `cpu`, `light`)
- Композиция job'ов: `probe → asr → clean → direct → render → upload`
- Прогресс в Redis, бот редактирует сообщение раз в 3 сек
- Лимит длины входного видео (начать с 90 сек, вынести в конфиг)
- Обработка падений: статус `failed` + внятное сообщение юзеру

**DoD:** отправил видео в телеграм → через N минут получил готовый ролик,
по пути видел прогресс.

**Это MVP. Здесь останавливаемся и показываем живым людям.**

---

### M5. Remotion и пресет Glass

Замена ASS на нормальный рендер.

- Remotion-проект, композиция `Reel`, `<OffthreadVideo>` как база
- `layers/Captions.tsx`: три состояния слова (ghost / active / past),
  `spring()` на появление, `backdrop-filter` на панель, flex-контейнер
  (сам растёт под контент)
- Пресет `glass.json`: цвета, шрифт, размеры, тип контейнера, тип анимации
- `render.mjs`: stdin JSON → mp4
- `pipeline/render.py`: subprocess-вызов

**DoD:** результат визуально соответствует референсам; смена `preset` в EDL
меняет вид без правки .tsx.

⚠ Шрифты ставить **в контейнер рендера**, иначе Chromium подставит дефолт.
⚠ `ensureBrowser()` при старте воркера, не при каждом рендере.
⚠ Кириллица: проверить, что выбранный шрифт покрывает весь диапазон.

---

### M6. Монтаж

- `cut.py`: применение `EDL.cuts` через concat demuxer с перекодированием
  (без него джамп-каты поедут по кейфреймам)
- Детекция тишины → `drop_silence` в EDL ещё на стадии восприятия
- `crop.py`: mediapipe → центр внимания по кадрам → сглаживание скользящим
  средним → динамический crop в 9:16
- `loudnorm` на звук

**DoD:** горизонтальное видео с паузами → вертикальное, ритмичное, лицо в кадре
и не дёргается.

---

### M7. B-roll

- `llm/prompts/plan_broll.md`, vision-вызов с 3-4 кадрами
- Pexels API → fallback на генерацию
- Кеш по хешу запроса в MinIO
- `layers/Broll.tsx`: анимации входа, включая fullscreen → inset

**DoD:** картинки появляются по смыслу, не перекрывают лицо, не более
одной на 8 секунд.

⚠ Запретить моделям рисовать текст на картинках, кириллицу они врут.
Надписи накладывать своим слоем.

---

### M8. Продукт

Пресеты как данные (5-6 штук), Telegram Mini App с правкой EDL на таймлайне,
перерендер из сохранённого EDL со сменой пресета, биллинг, лимиты.

## 6. Как вести работу

**Каждая сессия начинается так:**

1. Прочитай `PLAN.md` целиком
2. Назови текущую веху и её DoD
3. Предложи план файлов и функций, дождись подтверждения
4. Только потом пиши код

**Правила:**

- Тесты пишутся до реализации там, где есть чистая функция (EDL-валидатор,
  ASS-генератор, разбивка на блоки).
- Никаких заглушек, которые «потом заменим». Если внешний сервис не готов,
  делай реальный вызов на реальном ключе или останови работу и скажи об этом.
- Не рефактори то, что не относится к текущей вехе.
- Каждая веха заканчивается рабочей демонстрацией, а не «код написан».
- Секреты только через `.env`, никогда в коде.

**Стоп-сигналы (остановись и спроси):**

- Требуется поменять схему EDL → это архитектурное решение
- Нужна библиотека, которой нет в §1
- Пайплайн упирается в производительность

## 7. Что померить до масштабирования

Завести с первого дня, иначе экономика вскроется поздно:

- время ASR на минуту видео
- время рендера Remotion на минуту (самая дорогая позиция)
- токены и стоимость на ролик по каждому вызову LLM
- доля роликов, упавших на валидации EDL

**Эвал-сет.** 20 роликов с руками размеченными «правильными» акцентными словами.
Без него выбор модели для `direct` это вкусовщина. С ним это два часа
измерений и обоснованное решение.
