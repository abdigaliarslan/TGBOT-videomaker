# ReelBot: план улучшения качества картинки

Дополнение к `PLAN.md`. Фичи там, здесь только то, что делает результат «дорогим».

Порядок фаз не случаен. Ф1-Ф3 стоят часы и видны сразу. Ф4 это узкое горлышко,
через неё проходят Ф5, Ф7 и половина Ф6. Ф8-Ф9 доводка.

**Правило работы:** после каждой фазы рендерим один и тот же эталонный клип
(20 секунд, тот же исходник, тот же EDL) и складываем в `samples/phase-N.mp4`.
Без сравнения до/после оценить правку невозможно, всё будет казаться лучше.

## Ф0. Замерить базу (30 минут)

- Выбрать эталонный клип 20 секунд, зафиксировать его в репозитории
- Сохранить `samples/phase-0.mp4` и `edl-baseline.json`
- Вытащить полнокадровый скриншот: `ffmpeg -ss 5 -i out.mp4 -frames:v 1 f.png`
- Померить долю лица по высоте кадра (ориентир 20-25 %)
- Проверить `words.json` на монотонность: `w[i].end <= w[i+1].start` для всех i.
  Нарушения означают, что тайминги врут и анимация подсвечивает не то слово.

**DoD:** есть базовый сэмпл и два числа: доля лица, количество немонотонных пар.

## Ф1. Косметика (один вечер)

Всё мелкое, всё видно сразу, ничего не ломает.

| Что | Где | Как |
|---|---|---|
| Убрать обводку текста | `Word` в TSX | выкинуть `WebkitTextStroke`, оставить многослойную мягкую тень |
| Срезать пунктуацию | `clean.py` | точки, запятые, тире, многоточия. Сохранить дефис внутри слова и апостроф |
| Поднять контраст панели | `glass.json` | `opacity` 0.32 → 0.5, `blur` 18 → 24 |
| Приглушить ghost | `glass.json` | `ghost_opacity` 0.3 → 0.0, место резервируется, слово не видно |
| Выключить shake | `direct.md` + схема | убрать из enum, из промпта, из TSX |
| Не резать сток по центру | `Broll` в TSX | `objectPosition: "center 30%"` |
| Потолок картинок | валидатор | было `ceil(dur/8)`, стало `min(2, ceil(dur/12))` |
| Запрет абстракций | `plan_broll.md` | иллюстрировать только конкретные референты: предметы, места, названия, числа. Абстрактные существительные и метафоры пропускать |

Обводка это главный пункт списка. Жирный шрифт с чёрным контуром читается как
дефолтный шаблон монтажки, а с панелью она вдобавок избыточна.

Ghost в 0.0 с сохранением места: `visibility: hidden` или `opacity: 0`, layout
не двигается, инвариант «контейнер не прыгает» сохраняется, а визуального шума нет.
Для пресета `bold` (панели нет) ghost можно оставить видимым, там он часть стиля.

**DoD:** `samples/phase-1.mp4` рядом с базой, разница видна на статичном кадре.

## Ф2. Звук (один вечер)

Сейчас в пайплайне восемь этапов и ни одного про звук. Это самая большая
недостача на единицу трудозатрат во всём документе.

Новый этап `audio_post` между `cut` и `render`, целиком на ffmpeg:

1. `loudnorm` на голосовую дорожку, цель −16 LUFS
2. Музыкальная подложка из папки `assets/music/`, выбор по пресету
3. Дакинг: `sidechaincompress` музыки под голос, порядка −12 dB
4. `whoosh` на резах с punch-in и на входе картинки, из `assets/sfx/`
5. Фейд музыки 0.5 с на входе и выходе

Треки и эффекты брать с freesound или другой библиотеки со свободной лицензией.
Лицензии проверить до, а не после запуска.

Слой в EDL:

```python
class Sfx:   at_word_idx: int; name: str; gain_db: float = -6.0
class Music: track: str; gain_db: float = -20.0; duck_db: float = -12.0
```

Расстановку `sfx` делает Python по уже готовым резам и картинкам, LLM тут не нужна.

**DoD:** ролик со звуком, речь ровная по громкости, музыка не забивает голос,
на входе картинки слышен whoosh.

## Ф3. Цветокор (2 часа)

Пользователи будут присылать тёмное плоское видео с телефона. Хорошие
инструменты незаметно вытягивают картинку.

Новый фильтр в `crop.py` или отдельным шагом:

```
eq=contrast=1.08:saturation=1.12:gamma=0.98,
vignette=PI/5
```

Значения вынести в пресет (`grade` секция), чтобы стили отличались не только
шрифтом. Опционально мягкий LUT через `lut3d`.

Осторожно: не переборщить, `saturation` выше 1.2 на лицах даёт красноту.

**DoD:** сравнение до/после на тёмном исходнике, картинка читается лучше,
кожа не поехала в цвете.

## Ф4. Метрики шрифта и геометрия в Python  ← узкое горлышко

Корень проблемы, описанной в §8.4 аудита: геометрия живёт константами в TSX,
Python оперирует половинами кадра.

Лечится не переносом констант, а тем, что Python учится точно мерить текст.

1. Скрипт `tools/font_metrics.py`: fontTools открывает TTF, выгружает
   `{glyph: advance_width_em}` плюс `units_per_em`, `ascender`, `descender`
   в `presets/metrics/<font>.json`. Запускается один раз при добавлении шрифта.
2. Модуль `core/geometry.py`:
   - `measure_word(text, font_size) -> float`
   - `measure_line(words) -> float` с учётом разных кеглей в строке
   - `caption_rect(block, preset, frame_size) -> Rect`
   - `broll_rect(anchor, preset, frame_size) -> Rect`
3. Все константы из TSX (`INSET_RATIO`, `MARGIN`, `0.16`, `0.58`) переезжают
   в пресет. TSX читает готовые прямоугольники из плана и не считает ничего сам.
4. `RenderPlan` получает поля `caption_rect` и `broll_rect` на каждый элемент.

Проверка: рендерим кадр, накладываем прямоугольники из Python, они должны
совпасть с реальными пиксельными границами.

**DoD:** тест, который сравнивает предсказанную Python ширину строки с
измеренной `measureText` в Node. Расхождение меньше 2 px.

## Ф5. Акцент и перенос строк (после Ф4)

**Акцент переезжает в layout.** Вместо `transform: scale(accent_scale)` ставим
`fontSize: base_size * accent_scale` прямо на спане. Flex меряет правильно,
`gap` работает, `flexWrap` работает, наезда нет по построению.

`pop` остаётся, но становится транзиентным и маленьким: `scale` 1.0 → 1.05 → 1.0
за 180 мс. На таком масштабе он физически не может наехать на соседа.
`pop_scale` в пресете снизить с 1.16 до 1.05, из `bold` с 1.24 до 1.06.

Убрать перемножение `pop_scale` с `accent_scale`, это была причина пиков 1.5.

**Перенос строк в пикселях.** `wrap_words` по символам выбрасывается целиком.
Новая версия использует `measure_word` из Ф4, учитывает разные кегли слов в
блоке, ширину эмодзи и реальную ширину пробела (не `gap`, а именно пробел).
`max_line_chars` из пресетов удаляется, вместо него `max_line_width_ratio`.

Длинное слово, которое не влезает в строку в одиночку: уменьшать его кегль
до влезания, а не переполнять контейнер.

**DoD:** прогон по 30 роликам, ни одного случая, где текст выходит за
`caption_rect` или слова перекрываются. Тест автоматический, через `measure_line`.

## Ф6. Кадрирование и движение

**Правила кропа** в `crop.py`:

- Целевая доля лица по высоте кадра: параметр `face_height_ratio`, старт 0.22
- Масштаб кропа выводится из неё, а не из вписывания bbox
- Жёсткий кламп: масштаб не больше 1.0 относительно исходника. Вертикальный
  вход не должен зумиться вообще
- Линия глаз на 0.36 высоты кадра, не по центру
- Верх головы плюс headroom обязан влезать, иначе уменьшаем масштаб
- Сглаживать прямоугольник кропа, а не позицию лица

**Движение через смену крупности на резе.** `CameraMove` удаляется из EDL,
вместо него:

```python
class Cut:
    src_in: float
    src_out: float
    reason: Literal["hook", "keep", "drop_silence", "drop_filler"]
    framing: Literal["wide", "tight"] = "wide"     # ← новое
```

`wide` = `face_height_ratio` 0.22, `tight` = 0.28. Чередование ставит Python
по готовым резам, LLM не участвует. Движение мотивировано монтажом, происходит
в момент реза, не спорит с субтитрами и не требует новой физики.

Заодно исчезают все дефекты §8.2: нет синуса по номеру кадра, нет пружин на
3 кадра, нет пересекающихся окон, нет зависимости от fps.

**DoD:** доля лица в кадре в диапазоне 0.20-0.30 на всех сегментах,
макушка не обрезана ни разу, смена крупности на резах читается.

## Ф7. Картинки (после Ф4 и Ф6)

**Формат подачи.** По умолчанию полноэкранная вставка на 1.5-2.5 секунды,
не угловой инсет. Инсет в углу поверх говорящей головы читается как
новостная плашка. `fullscreen_to_inset` оставить, но с исправленной геометрией.

**Геометрия из Python.** `broll_rect` считается в Ф4, TSX его исполняет.
Правило разведения с субтитрами становится настоящим пересечением
прямоугольников вместо половин кадра. Заодно чинится логическая инверсия в
`occupied()`: `center` больше не помечает обе половины занятыми.

**Пропорции.** Карточка не квадратная, а наследует пропорцию источника
(сток отдаёт 2:3). Тогда `cover` почти ничего не режет.

Во время `fullscreen_to_inset` интерполировать не `width` и `height` по одному
`k`, а масштаб и позицию при фиксированной пропорции. Сейчас пропорция бокса
плывёт с 9:16 до 1:1 и содержимое дышит на каждом кадре.

**Тайминги.** Минимальная длительность для `fullscreen_to_inset` поднять
до 1.6 с (сейчас 0.8 физически не успевает). Вход и выход одной природы:
оба через `easeOut`, а не пружина на вход и линейка на выход.
`durationInFrames` привести к натуральной длительности пружины, не сжимать в 1.8 раза.

**Смысл.** Правило из Ф1 уже стоит в промпте, здесь добавить постфильтр в
Python: если `query` состоит только из абстрактных слов по стоп-листу, вставку
выбрасываем молча.

**DoD:** картинка ни разу не пересекает `caption_rect`, не режет объект,
появляется и уходит плавно, на 20-секундном ролике их не больше двух.

## Ф8. Тайминг анимаций

Мелкая доводка по числам из §8.3 аудита.

- `durationInFrames` всех пружин привести к натуральной длительности,
  сжатие в 1.8 раза даёт обрыв на максимуме скорости
- `framesIn` считать от округлённого до сетки кадров старта, иначе первый
  кадр стартует с альфы 0.09-0.45 и момент появления гуляет
- Нахлёст блоков субтитров 200-250 мс: уходящий блок ещё виден, когда
  приходит новый. Сейчас `presence` берёт минимум из двух и они не пересекаются
- Выход блока через `easeOut`, не линейно
- Все анимационные поля пресета масштабировать в `scaled(height)`,
  сейчас масштабируются только шесть полей размеров

**DoD:** покадровый прогон анимаций, ни одна не короче 8 кадров при 30 fps.

## Ф9. Контраст как ограничение

Панель фиксированной прозрачности не справляется над светлым фоном.

В препроцессе считать среднюю яркость области под `caption_rect` (numpy по
3-4 сэмплам на блок, стоит копейки), класть в EDL:

```python
class CaptionBlock:
    ...
    bg_luma: float | None = None    # 0..1, заполняет Python
```

Рендерер подбирает `panel.opacity` и цвет текста так, чтобы контраст
гарантированно превышал порог. Это единственное место, где стиль уступает
измерению, и именно оно отличает коммерческий инструмент.

**DoD:** ролик над светлым и над тёмным фоном, текст читается одинаково.

## Параллельный трек: фундамент распознавания

Не фаза, а отдельная задача, которую стоит начать рано, потому что от неё
зависит попадание анимации в речь.

- `faster-whisper small` → `medium` или `large-v3`
- Форсированное выравнивание через wav2vec2 (WhisperX) вместо таймингов
  из кросс-аттеншена
- Проверка монотонности `words.json` в валидаторе, не только в тесте

Если подсветка иногда опаздывает на слово, никакая типографика этого не спасёт.
