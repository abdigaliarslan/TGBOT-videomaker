# ReelBot

Телеграм-бот для автоматического монтажа вертикальных роликов: пословные
субтитры с акцентами, вырезание пауз, автокроп 9:16 с трекингом лица, вставка
картинок по смыслу.

Спецификация — [`plan.md`](plan.md). Этот файл про то, как запустить и что уже
работает.

---

## Архитектура

```
Восприятие (детерминированное)  →  LLM-режиссёр (JSON)  →  Рендерер (тупой)
```

**EDL** ([`src/core/edl.py`](src/core/edl.py)) — контракт системы. Модель никогда
не рендерит и не считает арифметику: она возвращает JSON со ссылками на индексы
слов, таймкоды подставляет Python из вывода ASR. Рендерер ничего не решает —
получает готовые секунды и рисует буквально.

Из этого следует всё остальное:

| Правило | Где закреплено |
|---|---|
| LLM не возвращает таймкоды, только `word_idx` | схемы в [`src/llm/schemas.py`](src/llm/schemas.py) — в них нет ни одного поля со временем, есть тест |
| Анимация — код, а не модель | [`render/src/layers/Captions.tsx`](render/src/layers/Captions.tsx) |
| Пресет — данные, а не код | [`src/core/presets/*.json`](src/core/presets/) читают оба рендерера |
| EDL переживает перерендер | EDL лежит в БД; `rerender_job` собирает новое видео без ASR и LLM |

### Поток данных

```
видео → probe → asr (пословно) → director (EDL) → broll → cut → crop → render → mp4
                                     │
                                     └─ валидация EDL → 1 ретрай → детерминированный фолбэк
```

## Запуск

### 1. Зависимости

```bash
python3.12 -m venv .venv
.venv/bin/pip install -e ".[dev]"
# ASR с форсированным выравниванием (см. «Про ASR» ниже)
.venv/bin/pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install whisperx

cd render && npm install && node render.mjs --ensure-browser && cd ..
```

### 2. Конфигурация

```bash
cp .env.example .env
```

Минимум для запуска — `BOT_TOKEN`. Всё остальное имеет рабочие значения по
умолчанию. Без `ANTHROPIC_API_KEY` режиссёр работает детерминированно: блоки по
паузам и лимитам, без акцентов и b-roll. Ролик всё равно соберётся.

### 3. Инфраструктура

```bash
docker compose up -d postgres redis minio
.venv/bin/python -m alembic upgrade head
```

Если порты заняты, переопределите `POSTGRES_PORT` / `REDIS_PORT` / `S3_PORT` и
согласуйте с ними `POSTGRES_DSN` / `REDIS_URL` / `S3_ENDPOINT`.

### 4. Локальный Bot API server (файлы до 2 ГБ)

Без него облачный Bot API ограничивает вход **20 МБ**.

1. Получите `api_id` и `api_hash` на https://my.telegram.org и впишите в `.env`.
2. Один раз выведите бота из облачного Bot API:
   ```bash
   curl "https://api.telegram.org/bot$BOT_TOKEN/logOut"
   ```
   Это односторонний переключатель: дальше бот работает только через ваш сервер,
   пока вы не выполните `logOut` уже на нём.
3. Поставьте `BOT_API_URL=http://localhost:8081` и поднимите сервис:
   ```bash
   docker compose up -d telegram-bot-api
   ```

⚠ Локальный сервер отдаёт **локальные пути к файлам**, а не URL.
`bot.download_file()` с ним не работает — файл читается напрямую с общего тома,
это делает [`Settings.bot_api_path_to_local`](src/core/config.py).

### 5. Воркер и бот

```bash
.venv/bin/python -m arq src.worker.tasks.WorkerSettings   # воркер
.venv/bin/python -m src.bot.main                          # бот
```

## Тесты

```bash
.venv/bin/python -m pytest              # быстрые, без моделей
.venv/bin/python -m pytest -m slow      # ASR, трекинг, рендер
.venv/bin/python tests/asr_accuracy.py  # измеритель точности таймингов
```

**Денежные тесты** (`tests/test_money.py` — списание, возврат, зачисление
оплаты) идут по НАСТОЯЩЕМУ Postgres: они держатся на транзакции и на условии в
WHERE, а это двойником не изобразить. Нужен поднятый постгрес
(`docker compose up -d postgres`); адрес переопределяется переменной
`TEST_POSTGRES_DSN`. Без базы они пропускаются — но в CI стоит
`TEST_POSTGRES_REQUIRED=1`, и там пропуск валит выкладку: гейт из пропусков не
сторожит ничего.

Фикстура собирается сама (`tests/fixtures/make_fixture.py`): речь синтезируется
ffmpeg-фильтром `flite`, а **границы речи замеряются по энергии сигнала**. Без
этого «эталон» совпадал бы с границами файла, а не с речью, и любое измерение
точности ASR было бы бессмысленным.

## Про ASR: почему whisperx, а не просто whisper

Измерено на фикстуре (15.5 с, 12 ядер, без GPU, модель `small`):

| Бэкенд | Скорость | Среднее отклонение | Максимум |
|---|---|---|---|
| `faster_whisper` | 0.23× реалтайма | 230 мс | 716 мс |
| `whisperx` | 0.30× реалтайма | **46 мс** | **101 мс** |

+30 % времени за пятикратную точность границ слов. Для пословных субтитров это
решающе: на 230 мс подсветка уезжает на слово вперёд, и ролик выглядит сломанным.

`ASR_BACKEND=auto` берёт whisperx, если он установлен, иначе faster-whisper.

## LLM: провайдер — это настройка

§4 требует один абстрактный клиент и тиры вместо имён моделей в логике. Провайдер
живёт на том же уровне: `LLM_PROVIDER=anthropic|deepseek|gemini`, и пайплайн о
нём не знает.

| Тир | Что делает | anthropic | deepseek | gemini |
|---|---|---|---|---|
| `cheap` | правки ASR, метаданные | haiku-4-5 | v4-flash | 3.1-flash-lite |
| `smart` | **режиссёр** — качество продукта | opus-5 | v4-pro | 3.1-pro-preview |
| `vision` | план b-roll по кадрам | sonnet-5 | v4-flash-vision-exp | 3.7-flash |

Провайдеры различаются в двух местах, и оба важны:

1. **Принуждение к схеме.** Anthropic и Gemini умеют ограничить ответ
   JSON-схемой. У DeepSeek `response_format: json_schema` сейчас отключён
   («This response_format type is unavailable now»), доступен только
   `json_object`. Поэтому для таких провайдеров схема кладётся в промпт, а
   форму ответа проверяет [`src/llm/jsonshape.py`](src/llm/jsonshape.py) —
   промпт это просьба, а не гарантия. Нарушение формы тратит тот самый
   единственный ретрай (§4), а не роняет ролик.
2. **Кеширование промпта.** У Anthropic явное (`cache_control`), у DeepSeek и
   Gemini автоматическое. Общее одно: системная часть неизменна и идёт первой.
   У DeepSeek кеш-попадание **в 30 раз** дешевле промаха — на этом и держится
   себестоимость.

## Себестоимость

Каждый вызов пишется в `llm_calls` с токенами входа, выхода и чтения из кеша;
кешированные токены считаются по своей, низкой ставке и не учитываются дважды.
`/stats` от админа показывает расход за неделю по типам вызова.

## Отступления от спецификации

Две штуки, обе с причиной:

1. **Детектор лица — YuNet из OpenCV, а не mediapipe** (§1).
   `opencv-python-headless` уже нужен пайплайну, а mediapipe тянет отдельное
   дерево зависимостей и пинит `protobuf<5`, ломая torch/whisperx в этом
   окружении. Интерфейс детектора абстрактный
   ([`src/pipeline/crop.py`](src/pipeline/crop.py)): добавить mediapipe — это
   добавить класс, не трогая остальное.

2. **ASR-бэкенд выбирается, а не прибит к whisperx** (§1).
   whisperx остаётся предпочтительным и выбирается автоматически; faster-whisper
   работает там, где torch не поставить. Оба дают один и тот же `list[Word]`.

## Известные ограничения

- **Локальный Bot API не запущен**: в `.env` пустые `TELEGRAM_API_ID/HASH`.
  Пока вход ограничен 20 МБ. Код перевода путей готов и покрыт тестами.
- **Нет `ANTHROPIC_API_KEY`**: режиссёр работает детерминированно. Вся обвязка
  LLM (structured output, кеширование, учёт токенов, ретрай, фолбэк) покрыта
  тестами на двойнике SDK, но на живой модели не прогонялась.
- **Генерация картинок пишет мусорный текст на предметах.** Проверено на реальном
  вызове: даже с длинным негативным промптом диффузия рисует поддельные надписи.
  Против этого — ракурс без надписей в промпте и приёмка vision-моделью
  (`BROLL_VERIFY`) с одной перерисовкой; не помогло — вставка отменяется.
  Запасного стока нет: вставки только рисуются.
- **Эвал-сета нет** (§7). 20 роликов с размеченными вручную акцентными словами
  нужны до того, как выбирать модель для `direct`.
- **Рендер — самая дорогая позиция**: ~3.9× реалтайма на 12 ядрах без GPU.
